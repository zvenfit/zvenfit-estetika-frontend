# Попытки и успешные отправки форм

## Контракт фронтенда

Фронтенд передаёт в `window.dataLayer` два события:

| Событие | Когда возникает | Назначение |
|---|---|---|
| `form_submit_attempt` | Активация кнопки отправки мышью или клавиатурой, включая Enter в поле формы, до проверки полей | Анализ попыток и потерь в воронке |
| `form_submitted` | Успешный HTTP-ответ API с `ok: true` и непустым `submission_id` сохранённого обращения | Конверсия в принятую заявку |

```js
{ event: 'form_submit_attempt', form_type: 'lead' }
{ event: 'form_submitted', form_type: 'lead' }
```

`form_type`: `lead` — заявка на запись; `newsletter` — запрос подписки на рассылку.

При незаполненных обязательных полях возникает только попытка. Если отправка
успешна — сначала одна попытка, затем одно событие успеха. Ошибки валидации,
сети, API, некорректный JSON и антиспам-ответ без ID не создают успешную конверсию.
HTTP 202 считается успехом: заявка сохранена, уведомление в Telegram может
ожидать доставки. Для рассылки успех означает запрос подписки, не её подтверждение.

Каждое новое нажатие доступной кнопки — отдельная попытка. Пока запрос выполняется,
кнопка заблокирована и новые попытки/запросы не учитываются. Автоматические сетевые
повторы не создают новых попыток. После ошибки ручная повторная попытка сохраняет
ID обращения; после успеха новая отправка получает новый ID и отдельную конверсию.

Попытка отслеживается на активации кнопки, а не одновременно на `click` и `submit`,
поэтому Enter и обычный клик не дублируются. Прямой программный `requestSubmit()`
сам по себе не считается нажатием кнопки и не создаёт `form_submit_attempt`.

В обоих событиях только `event` и `form_type`: без имени, телефона, Telegram, UTM,
полного URL или ID обращения. Существующая очередь `dataLayer` сохраняется;
при её отсутствии создаётся массив для последующей загрузки GTM. Сбой тега
аналитики не прерывает отправку формы и не меняет её успешное состояние.

## Настройка GTM

Контейнер: `GTM-KQT53D6V`. Деплой фронтенда сам по себе не переключает теги GTM.

1. Создать переменную типа «Переменная уровня данных», имя `form_type`, версия 2.
2. Создать триггер «Пользовательское событие», точное имя `form_submitted`.
   Для конверсии заявки задать условие `form_type` равно `lead`.
3. Для рассылки, если она есть на сайте, создать отдельный триггер с тем же именем
   события и условием `form_type` равно `newsletter`.
4. В существующих тегах конверсии заменить старые триггеры отправки формы
   (`gtm.formSubmit`) или видимости сообщения успеха на соответствующие новые.
   Не оставлять оба способа запуска одного тега: это может удвоить учёт.
5. Сохранить идентификаторы целей в тегах и кабинетах аналитики. Имя события GTM
   не обязано совпадать с именем цели. По опубликованной конфигурации,
   проверенной 9 ноября 2026 года: Метрика: цель заявки `form submitted` (с пробелом), цель рассылки `subscribe_newsletter`.
6. Для анализа попыток создать отдельный триггер «Пользовательское событие»
   с именем `form_submit_attempt` и нужным фильтром `form_type`. Привязать к нему
   отдельные теги/цели попытки. Не привязывать к нему цели успешной заявки.
7. В Preview проверить последовательность: одно `form_submit_attempt`, затем
   одно `form_submitted` с тем же `form_type` после принятой тестовой заявки.
   При ошибке валидации должна быть только попытка, без запроса и конверсии.
   Проверить получение обоих типов событий в подключённых системах.
8. Опубликовать контейнер после проверки и развёртывания фронтенда.

Для GA4 можно привязать тег события `generate_lead`, для других пикселей — их
соответствующий тег. Новый счётчик или повторную инициализацию существующих
Метрики/VK добавлять для этого события не нужно.

## Проверка кода

```bash
node --test scripts/__tests__/form-analytics.test.cjs
```

Это runtime unit-тесты настоящих клиентских скриптов с подставленным API:
попытки, приём 200/202, отложенный ответ, повторные отправки, ошибки, антиспам-ответ,
очередь до загрузки GTM и изоляция ошибки тега. Дополнительно в Chrome проверены
настоящая разметка всех трёх форм, клик/Enter, нативная валидация, блокировка
повторного клика и ответ API 202. API подставлен; реальные заявки не отправлялись.
Отсутствие `form_submitted` в Preview при клике с незаполненными обязательными
полями ожидаемо: браузер не отправляет такую форму.

Обработчики событий и защита повторной отправки добавляют менее 1 КБ исходного JS
без новых зависимостей. Лимит `localJavaScriptBytes` повышен с 23 000 до 24 000
байт; остальные ограничения размера и загрузки остаются прежними.
