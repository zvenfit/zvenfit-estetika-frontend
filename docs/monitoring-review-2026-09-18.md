# Проверка алертов ZvenFit Estetika — 18 сентября 2026

Проверены история 14 production-алертов в Monium за 4–18 сентября,
сохранившиеся Cloud Function logs через `yc`, фактические настройки двух версий
функции и GitHub Actions. Данные основного ZvenFit исключены.
Проверка 18 сентября выполнена только на чтение; production-настройки тогда
не изменялись. Последующие исправления описаны в [дополнении за 19 сентября](#доработка-19-сентября).

Главная подтверждённая проблема — периодические таймауты чтения очереди YDB
фоновым обработчиком Telegram. Дополнительно обнаружены два расхождения порогов
медленных операций с конфигурацией репозитория. После всех пяти подтверждённых
падений обработчик снова успешно завершал работу примерно через 30–33 секунды,
с пустой очередью. Последний проверенный heartbeat 18 сентября в 18:59 МСК
также показывает пустую очередь. Эти данные не доказывают отсутствие потерь
или задержек каждой отдельной заявки за весь двухнедельный период.

## Приоритеты

| Приоритет | Находка | Следующее действие |
| --- | --- | --- |
| 1 | Чтение `list_telegram_candidates` иногда исчерпывает обе попытки по 10 секунд | Разобрать запрос и индекс outbox, сопоставить с диагностикой YDB; установить источник задержки до изменения таймаутов |
| 2 | В production порог медленной операции 1000 мс, в коде/workflow fallback 3000 мс; Warning в Monium `>0.5`, desired `>1.5` | Определить намеренные пороги, устранить расхождение; изолировать переменную Estetika от общей `YDB_SLOW_OPERATION_MS` |
| 2 | Сырые логи хранятся 3 дня при необходимости анализа за 2 недели | Выбрать достаточный срок хранения либо сохранять безопасную сводку инцидентов при срабатывании |
| 3 | `Check upstream parity` упал 7 и 14 сентября | Проверить изменения upstream и обновить baseline после аудита |
| 3 | Smoke сообщает об отсутствии четырёх CDN security headers | Настроить заголовки и повторить проверку |
| 3 | График длительности функции p95 показывает «Нет данных» за последние сутки | Проверить фактические labels provider-метрики и selector графика |

## Подтверждённые ошибки и повторы в сохранившихся логах

Cloud Logging group: `e23fnr42117phjg4r2oe`, retention `259200s`.
Фильтр ресурса: только `d4eo2hs99oj4tv1cn0d8`
(`zvenfit-estetika-telegram-lead`). Верхняя граница выборки — 18 сентября,
19:00 МСК; первые доступные WARN/ERROR в полученной выборке — 15 сентября,
20:03 МСК. Ранние события уже могли быть удалены retention-политикой.

Получено 361 сообщение WARN/ERROR, из них:

- 5 `ydb_operation_failed` и 5 соответствующих системных ошибок invocation;
- 23 `ydb_retry`, означающих успешное завершение операции после повтора;
- 16 `ydb_slow_operation`;
- 312 системных сообщений сборки/npm при развёртывании 17 сентября.

Системные ошибки и прикладное событие одного request сопоставлены между собой:
это **5 неудачных запусков, а не 10**. Строки npm также не являются отдельными
падениями функции.

| Время, МСК | Операция | Результат |
| --- | --- | --- |
| 15.09 20:03:47 | `list_telegram_candidates` | `TimeoutError`, 2 query attempts, около 20 секунд всего |
| 15.09 21:32:58 | `list_telegram_candidates` | То же |
| 16.09 12:44:50 | `list_telegram_candidates` | То же |
| 16.09 16:35:36 | `list_telegram_candidates` | То же |
| 16.09 17:55:37 | `list_telegram_candidates` | То же |

Во всех пяти случаях: `retriable=true`, `retry_attempts=1`,
`query_execute_attempts=2`, итоговая длительность 20005–20009 мс; системный
результат invocation — 502. По коду это чтение кандидатов из индекса outbox в
timer-ветке, до доставки Telegram. Эти пять ошибок не являются подтверждением
ошибок сохранения заявок через HTTP.

Для каждого из пяти эпизодов отдельно прочитаны INFO-логи соседних минут.
Первое успешное `retry_worker_completed` после ошибки появлялось через
30,2–32,5 секунды; `processed=0`, `outbox_pending=0`,
`oldest_pending_age_seconds=0`. Проверенные heartbeat в 18:58 и 18:59 МСК
18 сентября также содержат нули. Это подтверждает быстрое восстановление
фонового цикла и отсутствие накопленной очереди в этих конкретных точках.

Причина задержки внутри YDB/транспорта по имеющимся данным не установлена.
Признаков, достаточных для вывода о перегрузке базы, плохом индексе или проблеме
инициализации клиента, нет. Эти версии требуют отдельной диагностики.

Все 23 успешных повтора и 16 медленных событий также относятся к
`list_telegram_candidates`. Из 16 медленных событий 6 длились меньше 3000 мс;
они не попали бы в slow-log при fallback-пороге репозитория. Остальные 10
длились 6126–9957 мс и заслуживают разбора независимо от настройки Warning.

Событие `ydb_retry` пишется кодом после успешного возврата операции.
Пять неудачных повторов находятся в `ydb_operation_failed`, поэтому 23 —
число успешных восстановлений после повтора, а не общее число всех повторов.
Алерт «слишком много повторов» может оставаться зелёным при редких повторах.

## Расхождения конфигурации

| Настройка | Фактически в облаке | Репозиторий |
| --- | --- | --- |
| `YDB_SLOW_OPERATION_MS` | `1000` в предыдущей и текущей версиях функции | default/fallback `3000` |
| Slow YDB Warning | сумма за 10 минут `>0.5` | сумма за 10 минут `>1.5` |
| Slow YDB Alarm | `>2.5` | `>2.5` |
| `YDB_QUERY_TIMEOUT_MS` | `10000` | default/fallback `10000` |

Текущий Warning срабатывает уже на одно slow-событие, desired — на два.
Оба расхождения повышают чувствительность мониторинга, но не вызывают сами
таймауты YDB. Изменение порогов не устраняет ошибку чтения.

Workflow использует общее `vars.YDB_SLOW_OPERATION_MS`. Источник значения
`1000` не установлен: конкретная repo-variable не была получена (404),
чтение organization-variable недоступно имеющимся правам (403).
Фактическое runtime-значение при этом проверено непосредственно в версиях
функции. Делать вывод о конкретной organization-variable без доступа нельзя.

Источники: [workflow](../.github/workflows/main.yml),
[runtime defaults](../functions/telegram-lead/src/ydb/config.ts),
[desired alerts](../scripts/monitoring.config.json),
[live slow YDB](https://monium.yandex.cloud/projects/folder__b1ge1e4iopttj79hfdfm/alerts/folder__b1ge1e4iopttj79hfdfm_zvenfit_estetika_slow_ydb/view).

## CI и сопутствующие проблемы

- [7 сентября: upstream parity](https://github.com/zvenfit/zvenfit-estetika-frontend/actions/runs/34127632545)
  и [14 сентября: upstream parity](https://github.com/zvenfit/zvenfit-estetika-frontend/actions/runs/34852668940)
  завершились одинаковой ошибкой: `audit required; baseline=6065815 current=bd178b4`.
  Это требование аудита расхождения с upstream; подтверждения production-сбоя
  из этих двух CI failures нет.
- [Production deploy 17 сентября](https://github.com/zvenfit/zvenfit-estetika-frontend/actions/runs/35242280871)
  завершился успешно, включая smoke. PR checks того же дня также прошли.
- [Production smoke](https://github.com/zvenfit/zvenfit-estetika-frontend/actions/runs/35242280871/job/105275167429)
  вывел предупреждение об отсутствии CDN-заголовков `x-content-type-options`,
  `x-frame-options`, `referrer-policy`, `permissions-policy`, после чего
  завершился с `OK`. Это отдельный открытый вопрос конфигурации.
- При сборке функции npm писал `EBADENGINE`: пакеты YDB требуют npm >=10,
  а среда сборки сообщала npm 7.24.2 при Node 22.15.0. Установка завершилась
  успешно. Эти сообщения нельзя суммировать с ошибками рабочих invocation.
- На live dashboard график p95 длительности функции показал «Нет данных» за
  последние сутки при наличии heartbeat. В сохранённом selector используется
  имя функции в `resource_id`; [справочник provider-метрик](https://yandex.cloud/en/docs/functions/metrics)
  описывает для гистограммы ID функции. Это вероятное направление проверки
  selector, а не установленная причина отсутствия ряда в Monium.

## Ограничения выводов

История статусов изучена в браузере по календарным суточным группам
4–18 сентября UTC; 18 сентября — неполный день. Это не поминутная выгрузка
ровно 336 часов. Число независимых invocation за весь период не восстанавливалось
из долей цветов на графике: системная метрика имеет оконную семантику.

Сырые логи ограничены retention в 3 дня. Пять подтверждённых ошибок и 23
успешных повтора относятся только к сохранившейся выборке, а не ко всем двум
неделям. Причины более ранних Alarm и судьба каждой отдельной заявки не
подтверждены. Полный аудит всех live-настроек 14 правил не проводился:
для всех проверена история, конфигурационные расхождения установлены для
slow YDB и параметров функции.

## Доработка 19 сентября

Это дополнение к срезу 18 сентября; наблюдения выше сохранены как исторические.

- Источник runtime `YDB_SLOW_OPERATION_MS=1000` найден: переменная GitHub
  Environment `production` этого репозитория, обновлённая 12 августа
  в `21:08:57Z`. Первоначальная проверка repo/org variables не охватывала
  Environment variables. В локальном workflow теперь используется
  `vars.ZVENFIT_ESTETIKA_YDB_SLOW_OPERATION_MS` с fallback `3000`;
  имя runtime-параметра не изменено. Новая версия функции ещё не развёрнута.
- Live Warning для slow YDB сохранён и проверен в Monium: `>1.5`, то есть два
  события за 10 минут. Alarm `>2.5`, aggregation `sum`, delay `3m`, No data `OK`
  и email-уведомления с повтором раз в день сохранены. Это устраняет drift
  чувствительности, но не исправляет задержку YDB.
- Из опубликованного upstream `8e568f0` адаптированы диагностика успешных
  повторов YDB, нормализация числовых YDB status codes и Telegram failure phase.
  В Estetika наблюдается только стабильная `query_execute`; для остальных
  случаев пишется `unknown`. Число повторов и timeouts не увеличены, неоднозначный
  Telegram POST немедленно повторно не отправляется.
- Desired retention в конфигурации увеличена до 14 дней. Фактическая retention
  общей группы 19 сентября не подтверждена: запросы `yc`/IAM завершались
  таймаутом, а Cloud Console не загрузилась из-за таймаута `auth.yandex.cloud`.
  Это ограничение доступа при проверке, а не доказательство сбоя YDB или Logging.
  Изменение в Git само по себе не меняет Cloud Logging; старые удалённые логи
  восстановлены не будут.
- Выполнен [аудит паритета](upstream-parity.md) до
  `8e568f043f415b0b5109663dfa2662a4ff54e58b`; baseline обновлён локально.
  Lint, TypeScript, 73 unit-теста функции, тест deploy artifact, 45 тестов
  monitoring/deploy contracts и static build прошли. Visual suite не выполнила
  сценарии: отсутствует требуемый Chromium Headless Shell Playwright.

Код подготовлен локально, без commit/push/deploy. После его развёртывания нужно
проверить фактический slow threshold и новые поля следующего естественного
`ydb_retry`, а также retention общей группы. Отдельно остаются проверка p95
selector и CDN security headers; они не объявляются исправленными этим переносом.
